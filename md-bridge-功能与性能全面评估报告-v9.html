五、v9 实测新增缺陷清单（已亲自核验）

P1-顶格 · docx 内嵌图片静默丢失（docx→全部目标格式无图） 工程 CLOSED

位置：backend/app/importers/docx_importer.py（全文）· registry.py: register_importer("docx", import_docx)

证据链：① 竞技当时 docx_importer.py 无 drawing 关键字；② AST Image=0。本轮已 CLOSED：抽取在 docx_text（blip/pict），importer 文档+docling 合并路径均标注 drawing/blip；含图样本 Image≥1 且 md 内嵌 base64；门禁 test_docx_image_extraction / test_v9_arena_p0_p3。

影响：docx 是最主流输入格式，图片是其高频内容。静默丢弃（非报错、非占位）导致用户拿到无图文档而不自知——比 v8 的 xlsx mergeCells 往返断裂影响面更广。README「语义保真：标题、列表、表格、脚注、批注全链路」与 29 源格式宣称在此格式上不成立。

修复建议：在 docx importer 增加 media part 抽取（解析 w:drawing/wp:inline → a:blip r:embed → word/media/*，经 package relationships 定位），构造带 data + mime_type + alt_text 的 Image node（复用 docx_ooxml 的 zip 读取与 read_zip_member 工具），并补充图片往返测试。

P1 · 默认配置下 docx→md 被 anydoc fast 静默接管，「native 高保真」未生效 工程 CLOSED

位置：backend/app/config.py（anydoc_enabled=True · anydoc_formats 含 docx）· anydoc_bridge.py: should_handle()

证据链（竞技基线）：① 当时 docx→md ≡ anydoc fast；② native 曾因 RunStyle 洪水虚胖。本轮已 CLOSED：默认 anydoc_formats 排除 docx；bridge 注释改为 NATIVE FIRST : docx；列表 marker + chrome 跳过后 native 输出干净。

影响：① 「native 高保真 vs anydoc 快速」双通道的产品叙事与实际路由不符；② 运维关掉 anydoc 想切 native，会拿到列表语义更差的输出——配置成了一个陷阱。

修复建议：核对 anydoc_formats 默认值是否应排除 docx（回归「native 优先」设计意图）；修复 native md 导出列表 marker 丢失与空行泛滥（export_md 对 List Paragraph 需输出 - 前缀/编号），使 native 管线质量真正高于 fast 再开放切换。

P2 · native md 导出空行泛滥与列表拍平（内部管线质量缺陷） 工程 CLOSED

位置：backend/app/exporters/md_exporter.py: export_md()

同一样本：fast 887B vs native 完整管线曾 10,385B（约 12 倍）——根因是 enrich 把 styles.xml 整库 RunStyle 写入 AST，md 导出成海量 <!-- [run_style|degraded] -->。本轮已 CLOSED：md 跳过 chrome 目录节点；List Bullet→ListItem；实测含图+列表样本 ~150B 级干净输出。

P2 · markitdown 竞品参考：代码行首 # 被误判为标题 对照 · 已写实

位置：markitdown 0.1.7 行为（非 md-bridge 缺陷，列为行业对照）

代码段第二行 # 特殊字符: & < > | 保留测试 被 markitdown 输出为 H1。md-bridge：CodeBlock 原文进 fence；散文行首 # 由 md_escape 转义——门禁 test_p2_context_aware_escape_preserves_code_and_blocks。正面差异已写入 §六 markitdown 行。
