Formats

不是又一个转换脚本

所有格式先落到同一个 AST，再从 AST 写出。语义只解析一次，因此跨格式转换不会因为"链式中转"而逐层失真。

源格式

36 种 · 含 Office 二进制、旧式宏格式与电子书

docxdocdocm pdfpptxppt ppspotpptm ppsxppsmxlsx xlsxlsbxlsm odsodpodt mdhtmltxt csvrtfepub mobiazw3kf8 latexjsonmsg ipynbzippng jpgrssatom

目标格式

18 种文件格式 · rag 是导出模式，不计入这 18 种

mddocxpdf htmlxlsxpptx txtepubmobi azw3kf8latex csvodtods odpjsonrtf

导出模式 rag 写出 aduport.rag_elements JSON：切块、element_id、可选 embedding，直接喂给向量库。它不是文件格式。Pages / Numbers / Keynote 已摘牌。 自有的 pdf、rtf 再导入会保留标题、表格和图片。csv、txt 保留标题和表格的文字，图片只写成占位符。别人做的 PDF、没有正文段的 CSV、以及不成 Markdown 的纯文本，仍可能只剩段落。

Architecture

三层：使用面 / 转换内核 / 原生加速

Rust 写的 anydoc 负责独占 Office 与 ODF 的高保真解析，Python 层负责 AST 深度 enrich，两条路按需路由。

  ┌──────────────── 使 用 面 ────────────────┐
  │   Web UI · CLI · HTTP API · Python SDK    │
  └───────────────────┬──────────────────────┘
                      │  convert() / batch / jobs
  ┌───────────────────▼──────────────────────┐
  │   core/converter + registry（插件注册表）   │
  └───────────────────┬──────────────────────┘
                      │
      ┌───────────────┼───────────────┐
      ▼               ▼               ▼
 anydoc_bridge   native importers    ocr_engine
  (Rust 内置)     docx/pdf/md/…     MinerU / Paddle / docling
      └───────────────┼───────────────┘
                      ▼
             DocumentModel（AST）
      段落 / 表格(span) / 批注 / 脚注 / 公式 / 透视…
                      │
      ┌───────────────┼───────────────┐
      ▼               ▼               ▼
 md/docx/pdf/html  epub/mobi/azw3   xlsx/json/rtf/latex

表格 span 保真

合并单元格在 HTML / PDF / DOCX / PPTX / ODT / xlsx / JSON / MD / TXT / LaTeX / RTF 共 11 路共享同一套逻辑，不会"能转但表散了"。

语义节点保留

批注、脚注、修订痕迹、内容控件、文本框、透视表可一路带进 HTML / EPUB / DOCX / PDF / PPTX / XLSX / JSON。

PDF 双通道

导入：数字版优先走 pypdfium2 文本层，双栏启发式合并；导出：WeasyPrint 排版 + CJK 字体。

Access

四种接入方式，同一套内核

无论从哪进，转换结果完全一致——因为都走同一个 convert()。

Web UI

Vue3 单页，上传 / 预览 / 批量，双击启动脚本即用。

./start.sh

CLI

Typer 命令行，单文件与目录批量归档。

aduport convert a.docx b.md

REST API

FastAPI：同步转换、异步 Job、Webhook 回调、限流。

POST /api/convert

Python SDK

直接在业务代码里调 convert()，拿 AST 自行加工。

from aduport import convert
Private Deployment

为什么它天生适合私有化

目标场景是律所、政府与受监管企业的内部文档流转——这批环境的底线是「数据不出内网」。AduPort 从设计上就不依赖外部服务。

企业私有化包含

  • 一机一码 License — HMAC 签名绑定主机指纹，CLI 可签发与校验
  • 多租户 API Key — 任务按 tenant_id 隔离
  • HttpOnly 会话 + Job token — 会话密钥跨 worker HMAC，任务令牌一次性
  • 异步任务 + Webhook — 结果落盘，可回调你的系统
  • 离线预检 / 探活脚本 — 隔离网环境先跑一遍再装
  • 可观测 — Prometheus 模板：转换量、anydoc 命中率、OCR 状态、错误码
  • 离线包 — 源码 + native wheel + pip 缓存 + 校验和，可气隙交付

默认不包含

  • 公有云多租户计费门户 — 需单独定制
  • Pandoc / LibreOffice 打进主镜像 — 体积与许可边界，仅做调用适配
  • GPU OCR 集群 / 托管模型 CDN — 由客户侧提供
  • 渗透测试与正式认证函 — 单独 SOW

价格与折扣为合同议价，本页只描述交付范围。

FAQ

常见问题

会上传到你们的服务器吗？
自建与私有化部署不会——转换全程在你自己的机器上完成，默认不依赖任何第三方云端 API。公开演示实例是例外：它会接收你上传的文件用于转换，因此请勿上传涉密或敏感文档。
为什么不做成在线 SaaS 卖账号？
因为主要使用场景是律所、政府与受监管企业的内部文档流转，这批环境的要求就是数据不出内网。在线实例只作为体验入口，产品形态是私有化部署。这也是 PRICING_BOUNDARY.md 里把「公有云多租户计费门户」列为可选定制而非默认项的原因。
PyPI 上的包和私有化版本有什么区别？
PyPI 的 AduPort 是 MIT 开源、纯 Python，不含预编译的 Rust 扩展 aduport_native。native wheel 通过 GitHub Releases 或 Docker 提供。企业版额外含 License 校验、多租户、离线包与运维脚本，适用商业许可。
扫描版 PDF 能转吗？
能，但需要开启 OCR（MinerU / PaddleOCR-VL / docling），属于可选加购能力。OCR 需要额外模型与算力，服务等级中的 p95 指标不含 OCR。是否支持由 ocr_ready 健康检查给出。
转换保真度怎么验证？
最可靠的办法是拿你自己的真实文档跑一遍——尤其是表格合并单元格、批注、脚注这些容易丢的部分。开源版可以自行复跑 1193 项后端测试；企业采购前建议先用实际样本做一次验证。
价格是多少？
私有化部署按合同议价（人民币 / 美元），取决于席位数、是否需要 OCR、是否需离线包与支持等级。开源自建免费。请联系商务获取书面报价。
